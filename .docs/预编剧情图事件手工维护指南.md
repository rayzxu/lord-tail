# 预编剧情图事件手工维护指南

本文面向需要手工新增、修改和发布长期事件的维护者。预编剧情图用于“提前写好若干幕、允许分支、最后可靠收束”的事件，例如商队到访、数日后的审判、使团谈判或敌军逼近。它复用现有 Storylet、人物、场景、计划事件与历史系统，不是另一套 Quest 系统。

## 先选对事件类型

- 单次请愿、一次裁断即可结束：继续使用 schema v1 Storylet，参考 `.docs/Storylet事件手工维护与扩展.md`。
- 有 5–8 个子事件、分支与收束，或需要数小时/数日后继续：使用本文的 schema v2 Story Arc。
- 只需要“某日期提醒一次”，没有人物和分支：使用普通 scheduled event。

配置目录为：

```text
backend/app/data/storylets/
```

可复制的完整示例为：

```text
backend/app/data/storylets/spring_caravan_visit.json
```

Python 负责校验和执行，JSON 负责人物约束、冻结参数、节点、选项、效果、路径与系列复发规则。不要把具体货物、税额或剧情边硬编码进 Python。

## 最小剧情图

新建一个 snake_case 文件，例如 `abbey_relic_hearing.json`：

```json
{
  "schema_version": 2,
  "id": "abbey_relic_hearing",
  "version": 1,
  "title": "修道院圣物争议",
  "category": "court",
  "priority": "major",
  "scene_type": "court",
  "entry_node": "petition",
  "max_blocking_decisions": 2,
  "interaction_budget": {
    "default_max_freeform_steps": 2,
    "choices_visible_immediately": true
  },
  "roles": {},
  "parameters": {
    "verdict": {"constant": "undecided"}
  },
  "nodes": {
    "petition": {
      "kind": "choice",
      "title": "第一幕：院长请愿",
      "blocking": true,
      "narrative_template_md": "## 石厅中的请愿\n\n院长等待领主裁断。",
      "choices": [{
        "id": "hear_case",
        "label": "开庭审理",
        "description_md": "允许双方呈上证词。",
        "effects": [{"op": "set_arc_fact", "key": "verdict", "value": "hearing"}],
        "transition": {"to": "resolved"}
      }]
    },
    "resolved": {
      "kind": "terminal",
      "title": "终幕：卷宗封存",
      "blocking": false,
      "narrative_template_md": "## 封蜡落下\n\n书记官封存了本案。",
      "effects": [
        {"op": "append_history"},
        {"op": "resolve_entry_event"}
      ]
    }
  }
}
```

每个图必须有且只有一个 `entry_node`，所有节点必须从入口可达，所有路径最终必须抵达至少一个 `terminal`，第一版禁止环。

## 四种节点

| kind | 用途 | 必需字段 |
| --- | --- | --- |
| `choice` | 等待领主正式裁断 | `choices`，每项有一个 `transition` |
| `automatic` | 无需玩家决定的收束/过场 | `effects`，且必须有唯一 fallback transition |
| `timed` | 若干小时或天后再出现 | `after_hours` 或 `after_days`、`choices` |
| `terminal` | 结束整条事件 | `resolve_entry_event`，不得再有 transition |

推荐让一条路径最多包含三个 `blocking` 决策，并用 `automatic` 节点合并重复过场。`max_blocking_decisions` 会在加载时校验，防止事件再次变得拖沓。

## 写分支与收束

分支必须显式写在 choice 上：

```json
{
  "id": "inspect_outside",
  "label": "在城外验货",
  "description_md": "命卫兵在城外开箱。",
  "effects": [{"op": "set_arc_fact", "key": "entry_policy", "value": "inspection"}],
  "transition": {"to": "cargo_inspection"}
}
```

多条边可以指向同一个节点，这就是“收束”。不要使用 schema v1 的 `schedule_followup` 隐藏剧情边；schema v2 会拒绝它。

automatic 节点可以按冻结事实选择条件边，但必须保留一个无 `when` 的 fallback：

```json
"transitions": [
  {"when": {"fact_equals": {"inspection_result": "contraband"}}, "to": "confiscation_hearing"},
  {"to": "trade_hearing"}
]
```

当前条件白名单为：

```text
fact_equals / fact_gte / fact_lte / choice_was
resource_minimum / relationship_minimum / character_trait_minimum
season_any / any
```

添加新条件必须同时扩展 `backend/app/storylets/graph.py` 的校验和执行，并增加测试。

## 延时子事件

延时节点示例：

```json
"camp_outside": {
  "kind": "timed",
  "title": "六小时后的第二次求见",
  "after_hours": 6,
  "blocking": true,
  "narrative_template_md": "商队仍在界碑外等待。",
  "choices": []
}
```

实际使用时 `choices` 不能为空。运行时会创建绝对游戏时间的 `story_arc_node` 计划事件；如果到期时已有别的场景，它会排队，并在当前场景正常结束后激活。不要在文案中自行计算日期。

## 冻结人物与参数

`roles`、`parameters` 与 schema v1 共用选角和参数生成器。入口实例化时会冻结：

- `cast` 与 `cast_snapshots`；
- 货物、路线、金额、检查前提等 `facts`；
- 当前节点的 `choice_ids`；
- 系列事件的 `occurrence_key`。

后续节点复用同一份人物与事实。Hermes 只能演出这些数据，不能补造货物或替换商队首领。

剧情内更新事实使用：

```json
{"op": "set_arc_fact", "key": "trade_permission", "value": true}
{"op": "increment_arc_fact", "key": "merchant_attitude", "delta": -5}
```

其他资源、民心、统治力、人物记忆和历史效果继续使用 Storylet 现有 effect 白名单。金额和后果必须写进 JSON，不要交给 Hermes 决定。

## 终局与重复到访

terminal 至少包含：

```json
{"op": "resolve_entry_event"}
```

需要依据本次结局安排下次事件时，再加入：

```json
{"op": "schedule_series_occurrence"}
```

并在根节点配置：

```json
"series": {
  "id": "southern_caravan_route",
  "event_type": "caravan_arrival",
  "route_id": "southern_route",
  "outcome_fact": "departure_reason",
  "outcomes": {
    "normal_trade": {"in_days": 90},
    "refused": {"in_days": 180},
    "humiliated": {"schedule": false}
  },
  "default": {"in_days": 90}
}
```

运行时按 `occurrence_key` 查重。不要同时使用 catalog 的 generic seasonal repeat，否则会生成两支相同商队。带 `story_arc_definition_id` 的事件会自动禁用 generic repeat。

## 把图绑定到计划事件

生产入口仍是 scheduled event。通过后端代码或正式事件创建入口设置 flags：

```json
{
  "story_arc_definition_id": "spring_caravan_visit",
  "story_arc_seed": 2001,
  "series_id": "southern_caravan_route",
  "route_id": "southern_route",
  "occurrence_key": "caravan:southern_route:year_1:spring"
}
```

新开局春季商队在 `backend/app/engine/state.py` 中绑定。普通自定义图也应通过一个明确的事件模板和入口 flags 绑定。已经 active 的旧 generic 事件不要在存档 normalize 时偷偷转换。

## 修改与版本管理

- 未进入任何存档前：可直接编辑图并保持 `version: 1`。
- 已有玩家存档包含该图后：不要删除或改名已发布的 node/choice id；修改语义时递增 `version`。
- 改文案但不改规则：仍建议递增 version，便于诊断实例来自哪个版本。
- 已实例化的 cast/facts 是历史事实；JSON 修改不会也不应追溯改写。
- 删除事件前先确认没有 active chain 或未来 scheduled occurrence 引用它。


发布前人工检查：

1. 每条路径都到 terminal。
2. blocking 决策不超过配置上限。
3. 每个 choice 的玩家可见描述与实际 effects 一致。
4. terminal 解决入口事件，且下一次 occurrence 数量为 0 或 1。
5. Hermes 关闭时仅靠本地 Markdown 和按钮也能通关。
6. 刷新、保存和读取后仍恢复同一 current node、timeline 与 legal choices。

## 常见错误

- `transition 指向不存在节点`：拼错 node id。
- `存在不可达节点`：节点没有任何入口边。
- `第一版剧情图禁止环`：某条边返回了祖先节点；改成有限 DAG。
- `terminal 必须包含 resolve_entry_event`：终局没有正式解决入口事件。
- `automatic 必须有且只有一个 fallback`：缺少无条件边或写了多个无条件边。
- `blocking decision 最大深度超过限制`：裁断过多；合并节点或改为 automatic。
- 前端出现通用商队选项：入口事件没有 `story_arc_definition_id`，或场景 flags 未标记 `source=story_arc`。
- 事件无法结束：不要直接调用 scene end；应提交当前 legal choice，运行时抵达 terminal 后会原子结束。
